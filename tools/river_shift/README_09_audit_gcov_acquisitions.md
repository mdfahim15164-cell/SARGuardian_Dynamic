# 09 · Audit GCOV time-series comparability and AOI coverage

## Purpose
Determine whether a catalogue manifest contains at least three compatible NISAR GCOV acquisition dates for the same AOI. It groups products by maturity, orbit direction, relative orbit, bandwidth mode, polarization and processing configuration, then mosaics the product footprints available on each date and measures AOI coverage.

## Why this task is required
Three catalogue hits are not automatically a valid time series. Products can belong to different viewing geometries, polarizations, modes, processing releases or partial frame footprints. Pixel-wise analysis must not start until this audit reports a qualifying group and a human reviews the selected granules.

## Inputs
- A JSON manifest generated by README_01_discover_gcov_products.md.
- Manifest AOI in WGS84.
- Product maturity, orbit/track, frame, bandwidth mode, polarization and acquisition timestamp.
- Product footprint geometry or footprint WKT from ASF.
- Minimum dates (at least 3).
- Minimum AOI coverage percentage (default 90%; study team may raise it).

## Method
1. Validate the catalogue manifest and one WGS84 AOI polygon.
2. Select only records with explicit BETA/PROVISIONAL maturity and complete single-acquisition GCOV naming metadata.
3. Group records by maturity, orbit direction, relative orbit, bandwidth mode, polarization and processing type.
4. Within each group, aggregate footprints belonging to the same acquisition date.
5. Project the AOI and footprints to the locally appropriate UTM zone before calculating area.
6. Compute each date's union-footprint intersection area divided by AOI area.
7. Require at least three unique dates where the per-date footprint union meets the minimum AOI coverage threshold.
8. Retain every date, footprint percentage, granule ID, rejected item and caveat in the report.

Frame coverage (FULL or PARTIAL) is a NISAR product-frame metadata field. It is not the same quantity as the percentage of the user-defined AOI covered by a frame. The script checks the latter separately.

## Reproduce
    python audit_gcov_acquisitions.py --catalogue data-audit/gcov-catalogue-manifest.json --minimum-dates 3 --minimum-aoi-coverage-percent 90 --out data-audit/gcov-time-series-audit.json

Open GitHub → Actions → RiverShift NISAR GCOV catalogue audit → Run workflow. The default AOI is an explicitly unapproved Sirajganj–Kazipur candidate; replace it with the team-approved WKT before using the results as project evidence. The workflow produces downloadable catalogue and coverage-audit JSON artifacts. No Earthdata download credential is required for the public catalogue query.

## Outputs
- status: READY_FOR_THREE_DATE_SCREENING, INSUFFICIENT_COMPARABLE_ACQUISITIONS, or FOOTPRINT_DATA_INCOMPLETE.
- AOI area and UTM area-measurement CRS.
- Every compatibility group and date-level AOI coverage percentage.
- Granules selected for qualifying date groups.
- Rejected granule reasons and QA warnings.

## Acceptance tests
- Three unique dates from one compatible signature and at least 90% AOI coverage pass.
- Three dates on different relative orbits do not form one time series.
- Different maturity, direction, bandwidth or polarization split into separate groups.
- Partial footprints are unioned per date before area coverage is calculated.
- Missing/invalid footprints cannot be assumed to cover the AOI.
- A group with fewer than three eligible dates is not READY.
- No data, incomplete metadata and coverage failure remain distinguishable.

## Scientific limitations
- Catalogue and footprint intersection are not proof that the backscatter layer is scientifically comparable.
- Orbit, mode, polarization and release matching reduce but do not eliminate incidence-angle, terrain, calibration or hydrological-stage differences.
- Footprint coverage is a geometric availability check. It does not validate water detection or river migration.
- A large AOI can span multiple frames; this script mosaics same-date product footprints but does not resample raster data.
- Manual inspection in GIS is required before pixel-wise processing.

## AI reviewer checklist
- Verify output=json is requested from ASF and the exact source granule identifiers are preserved.
- Verify the official single-acquisition NISAR GCOV token layout is used.
- Verify maturity is explicit from the official collection path; unknown maturity is never guessed from dates.
- Verify grouping keys enforce comparable geometry and processing metadata.
- Verify every acquisition date passes the AOI coverage threshold.
- Verify the result status is not READY when footprints or metadata are missing.
- Verify the output is labelled catalogue/geometry feasibility, not completed scientific analysis.
